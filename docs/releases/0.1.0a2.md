# WeightLab 0.1.0a2 — Alpha 2: Visual Checkpoint Comparison

**Pre-release (alpha).** Upgrade from 0.1.0a1 with `uv tool install --force "weightlab==0.1.0a2"` once this version is published on PyPI.

Alpha 1 could explore one checkpoint in the browser and compare checkpoints only from the command line. Alpha 2 adds a **Compare** screen: pick a base and a derived checkpoint and see where their weights differ, by layer, by component role and by tensor. It shows how far the comparison can be trusted before it shows any number.

## Highlights

- **Compatibility first.** Every comparison opens with what is compared (A base → B derived, orientation B − A), the compatibility class (V verified base file, L declared or attested lineage, S no lineage evidence, X structurally incompatible), lineage evidence, matched/missing/tied/mismatched counts, and whether the report is complete. Classes S and X carry a prominent warning that element-wise differences of unaligned models may be meaningless.
- **Layer × role grid.** One cell per layer and component role (attention q/k/v/o, MLP gate/up/down, norms, embeddings, LM head, other), coloured by relative L2, delta L2, RMS, max |Δ| or cosine on a linear or log scale with a legend. Cells are computed only from their own tensors with the CLI's rollup arithmetic. Cosine is shown only where a cell holds a single tensor. The grid is keyboard operable, and selecting a cell filters the rankings.
- **Sortable rankings.** Tensor, layer and role tables with bars, filters and 100 rows per page. Withheld (overflow), undefined and non-aggregable values are labelled as such, sorted last, and never shown as zero.
- **Tensor drill-down.** Every metric with its method and numeric precision, element counts and non-finite values per side, caveats, and **Inspect in A / Inspect in B** opening the tensor in the existing explorer.
- **Analysis jobs you control.** Run, cancel and re-run, best effort or **verified** (SHA-256 of every input before and after). Progress and bytes read are shown, the job is rediscovered after a page reload, and every failure comes with the action that resolves it.
- **Snapshot freshness.** A report is a snapshot of the bytes it read. If a model file changes afterwards, the dashboard says so, and a re-run is refused until the model is re-imported.
- **Same numbers as the CLI.** The server computes reports with the engine behind `weightlab diff`, and the tests require identical output on fixtures and on real checkpoints.

## API and data (contract 0.4.0, ADR-020)

Additive to contract 0.3.0; no existing field, route or behaviour changes meaning.

- New job kind `comparison_report` (`POST /jobs` with `comparison_id`, `consistency`, `budget`).
- `GET /comparisons/{comparison_id}/report`: the stored report (paths redacted) with `complete`, `consistency`, `created_at` and `current_model_status`.
- `GET /projects/{project_id}/comparisons`. `Comparison` gains `policy`, `report` and `latest_report_job_id`.
- A report is published in the same transaction that marks its job completed. Failed, canceled, interrupted and crashed jobs publish nothing. A report is replaced only by a later-submitted job.
- Policy `strict` (default) reports Class V and L only and refuses S and X with 409 `LINEAGE_UNVERIFIED`. `descriptive_only` acknowledges descriptive use of raw coordinates.
- Limits, refused before queueing: at most 32,768 tensor entries, a memory reservation of 128 MiB + 16 KiB per entry within the job budget, and at most 128 MiB of report JSON.
- Database migration 0003 is applied automatically when a 0.1.0a1 data directory is opened, and keeps existing data.

## Evidence

- **Fixtures:** browser E2E on a real `weightlab start` checks that the ranking and every relative L2 equal `weightlab diff`, and runs axe (WCAG 2.x A/AA) in light and dark themes. See the screenshots in [evidence/alpha2-compare](../../evidence/alpha2-compare/README.md).
- **Real checkpoints:** on the pinned Qwen2.5-0.5B and Qwen2.5-Math-1.5B base/Instruct pairs, the stored reports are identical to `weightlab diff` in both consistency modes. Wall time was 5–21 s and server peak RSS at most 98.6 MiB, measured on an Apple M3 Pro with 36 GiB RAM and a warm page cache ([details](../../evidence/alpha2-compare/README.md#real-checkpoints)).

## Upgrade notes

- **Comparisons created with 0.1.0a1 cannot be analysed.** They lack the record fields that detect drift, so report jobs refuse them with `CONFLICT`. Create the comparison again; the Compare screen explains this.
- New comparisons default to the **strict** policy. Pairs without lineage evidence, including most Hugging Face base/fine-tune pairs, need **Descriptive only**.

## Known limitations

- **Summary metrics only:** no element-wise delta heatmap (B − A) and no LoRA overlay in the UI yet. The drill-down shows the delta heatmap action as unavailable. LoRA analysis remains CLI / Python only.
- Reports are not paginated: checkpoints with more than 32,768 tensor entries are refused, and a report must fit the job's memory and time budget (raise `memory_budget_mib` / `max_job_seconds` in Settings).
- Very wide grids scroll inside their panel; there is no zoom.
- Compatibility class V needs the derived checkpoint to name its base file's SHA-256. Real Hugging Face pairs are usually Class S.
- Weight changes are not evidence of behaviour, accuracy or capability changes.
- **Not verified:** the 8 GiB laptop target, browsers other than Chromium, and a practitioner usability study.
- SafeTensors only. No inference, activations or evaluation.
