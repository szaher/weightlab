## How to review

**B1, database (`weightlab/db/`).**

1. Read `migrations/0001_initial.sql`. It is doc 10 §3 as written, plus marked `ADDED` lines, each with its reason.
2. Then read `schema.py` (bootstrap) and `store.py` (repositories).
3. The tests `tests/db/test_migrations.py` and `tests/db/test_store.py` show the guarantees:
   - a fresh database is created and migration is idempotent;
   - a newer or edited database is refused and left unmodified;
   - a backup is taken before an upgrade;
   - a failed migration rolls back atomically;
   - FK, CHECK and UNIQUE constraints hold, and deleting a project cascades.

**B2, API (`weightlab/api/`).** Suggested order:

1. **`config.py`:** loopback-only bind; a fresh `token_urlsafe(32)` per launch.
2. **`security.py`:** the `Guard` ASGI layer. It checks, in this order:
   - Host allowlist;
   - Origin = `http://` + Host;
   - `/api/v1` only;
   - bearer token, compared in constant time;
   - 1 MiB body cap (413);
   - 16 requests in flight (429).

   It then sets the security headers and strips any CORS headers.
3. **`schemas.py`:** strict, `extra=forbid` mirrors of the contract's request schemas.
4. **`errors.py`:** the doc 09 §7 envelope and status mapping.
5. **`app.py`:** routes.
6. **`catalog.py`, `relations.py`, `roi.py`:** reuse of the Phase 0/0.5 reader, compatibility, lineage and LoRA code.

The contract tests are in `tests/api/`:

- `test_contract_schemas.py`: the contract examples, plus 1,808 generated mutations judged by both Pydantic and the frozen JSON Schema, which must agree;
- `test_routes.py`: route table = contract;
- every response body is validated against the contract's schema for that route and status (`tests/api/contract.py`).

**A, evaluation kit (`evaluation-kit/`, `scripts/build_evaluation_kit.py`).**

1. Read `evaluation-kit/README.md` as a participant would.
2. Run `uv run python evaluation-kit/run_examples.py`.
3. Read `QUESTIONNAIRE.md`, `COORDINATOR.md` and `FEEDBACK_SUMMARY_TEMPLATE.md`.

`uv run python scripts/build_evaluation_kit.py` builds `dist/weightlab-evaluation-kit-<version>.zip`. Checked so far:

- **Contents:** the docs, the wheel and the needed fixtures (copied unmodified), with `SHA256SUMS`.
- **Self-check:** the build unpacks the archive and runs the packed checks itself.
- **Deterministic:** two builds gave the same SHA-256.
- **Clean install:** from the archive into a new Python 3.12 venv; all checks passed on macOS.
- **Not yet done:** install on Linux or Windows.

## Specification gaps and decisions needing ADRs (spec not edited)

**Contract gaps.** These are statuses that doc 09's behaviour rules require but the frozen `openapi.yaml` does not declare for the route. They are listed in `tests/api/contract.py::CONTRACT_GAPS`; their bodies are still validated against `Error`.

| Route | Status | Why it is needed |
|---|---|---|
| GET `/projects/{id}/models`, `/adapters`, `/bookmarks`; POST/DELETE bookmarks | 404 | unknown project or bookmark |
| GET `/comparisons/{id}/entries` | 422 | invalid filter or page |
| POST `/models/{id}/relink` | 403, 422 | path outside the root; invalid body |
| POST `/projects/{id}/adapters` | 403, 413 | path outside the root; resource limit |

**Spec gaps resolved in code:**

1. **No `INTERNAL` error code** in the contract enum. Unexpected exceptions answer 500 with code `CONFLICT` and a generic message, and no exception text is sent (`app.py`).
2. **`relative_abs` is named but not defined** in the contract. Implemented as |B − A| / max(|A|, ε), with the formula returned in the ROI warnings (`roi.py`).
3. **Role enum has no fused-attention value.** `attention.qkv` (fused QKV) from the Phase 0.5 role heuristics is exported as `other` (`catalog.py`).
4. **Settings are application-wide**, as GET/PATCH `/settings` imply. Doc 10 has only per-project `settings_json`, so they are stored in a one-row `app_settings` table (ADDED).
5. **Schema additions the contract needs**, each marked `ADDED` in `0001_initial.sql`:
   - migration checksums;
   - `ON DELETE CASCADE`;
   - `Model.warnings`;
   - tensor `numel` and byte extents;
   - adapter lineage and file fingerprints;
   - a `comparison_entries` table;
   - ownership indices.
6. **Integral floats such as `1.0` are rejected where an integer is required** (strict Pydantic). JSON Schema accepts them. This is the only known difference in the differential test.
7. **`DELETE /projects/{id}?purge_cache`** is accepted, but there is no cache until Phase 1 task 4.
8. **`/health` `capabilities`** is the empty list until optional features exist.
9. **doc 12 vs fixtures.** Doc 12 names `PATH_OUTSIDE_ROOT` for lexical index paths, but the frozen `path_traversal` fixture expects `INVALID_FORMAT`. The fixtures win, as in Phase 0/0.5.
10. **Security choices the spec leaves open:**
    - 16 requests in flight before 429 (the 1 MiB body cap is doc 12 §4's default);
    - non-loopback `--host` values refused, including `localhost` (resolution could leave loopback); exit status 2.

## Known limitations

- **Single process, single user.** SQLite runs in WAL mode with `BEGIN IMMEDIATE` writes. There is no multi-process server.
- **Stale detection uses quick fingerprints:** relative path, size, `mtime_ns` and `dev:ino`. As in Phase 0/0.5 `best_effort`, a same-size rewrite that preserves the mtime is not detected until a read sees different bytes.
- **The token is printed once**, in the terminal URL's fragment, and is never logged. Anyone who can read that terminal can use the API until the process stops.
- **The evaluation kit has not been tried by anyone outside the project.** Its time estimates (30 minutes in total) are the author's guesses, and the first participants will test them.
