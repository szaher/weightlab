## What was built

- `weightlab diff BASE DERIVED` and `weightlab diff BASE --adapter DIR`, on the Phase 0 reader (positioned reads, no mmap, `FILE_CHANGED` detection).
- **Compatibility classes:**
  - X/V/L/S with reasons;
  - unmatched, tied and renamed-suspected entries listed first;
  - ties only with `tie_word_embeddings: true` plus a known key mapping.
- **Lineage evidence:**
  - SHA-256 manifest (`--lineage-manifest`, `--trust-manifest`);
  - Hugging Face cache blob SHA-256 for the declared repo and revision;
  - the fixture generator registry;
  - `--attest` (L, never V);
  - adapter `base_model_name_or_path` (L);
  - a contradicted claim gives S.

  `transfer_eligibility` T1–T5 is reported as a label only.
- **Exact streaming metrics per tensor:**
  - delta L2/RMS, relative L2 (ε visible), cosine, max-abs delta, norms;
  - finite, non-finite and changed counts.

  Rollups by layer and role, and a ranking by any metric.
- **LoRA effective delta** s·(B@A):
  - computed in row blocks, compared with the base like a pair;
  - modules over budget get the exact Gram-trace norm.
- **Exports:**
  - `report.json` (schema `weightlab/schemas/change_report.schema.json`; `Metric` and `LineageAssessment` validated against `contracts/openapi.yaml`);
  - `tensors.csv`, `layers.csv`, `roles.csv`;
  - `report.md`.
- Reference: `docs/cli/weightlab-diff.md`.

## PR #2 review fixes

All 11 findings of the PR #2 review were fixed in code. The spec is unchanged. Each fix has a test in `tests/integration/test_review_regressions.py` (37 tests). Run against the pre-fix code, 33 of them fail; the other 4 are controls (zero/negative limits the CLI already rejected, and a repo id that must not be redacted).

| # | Finding | Fix |
|---|---|---|
| 1 | Rollup relative L2 ignored ε | One `relative_l2(ssq_delta, ssq_ref, ε)` policy for tensors, modules and rollups; rollups carry `near_zero_reference` |
| 2 | NaN/Inf accepted for limits | `Options.validate()` (library and CLI): ε finite in [1e-300, 1], `max_lora_gmac` finite in [0, 1e6], `chunk_elements` in [1, 2^26] |
| 3 | I64/U64 deltas lost to float64 | Exact delta via 32-bit halves, then a single rounding; 2^53 vs 2^53+1 gives 1, and random int64 pairs match Python integers |
| 4 | Gram fallback false zero | Factors scaled by exact powers of two, exponent carried separately; NaN/Inf factors or cancellation within the rounding bound → withheld, never 0. Rank-1 1e100×1e100 gives 1e200 |
| 5 | LoRA overflow masked as invalid pairs | Overflow of s·B@A or W + s·B@A with finite inputs counted in `delta_overflow` / `b_overflow`; metrics `overflowed`; the report is incomplete (`modules_withheld` / `tensors_withheld`), in pair mode too |
| 6 | No hard Gram scratch limit | Working set (factors + Gram or row-block scratch) estimated from shapes before loading; above 384 MiB → `skipped`, nothing allocated; r ≤ 65536 |
| 7 | Over-budget relative L2 null for zero base | Same ε policy, with a `near_zero_reference` warning |
| 8 | Over-budget finite counts assumed | Base NaN/Inf counted and excluded from ‖W‖ (`finite_count`, warning); non-finite factors withhold the norm |
| 9 | Local `base_model_name_or_path` leaked | Anything not a plain `name` / `org/name` repo id is exported as `<local path redacted: NAME>` (lineage reasons included) unless `--include-paths` |
| 10 | Report files published one by one | `write_report_set`: stage + fsync all files, then commit with Ctrl-C deferred and rollback on a failed rename; a new `--out` directory appears with one rename |
| 11 | Huge JSON numbers crashed | Non-float64-representable alpha and out-of-range r give `INVALID_FORMAT` (exit 2) or an unsupported module |

The fixes changed no metric value: all 290 Qwen pair rows, all 168 LoRA module rows and all fixture rows are identical to the pre-fix reports. The goldens gained only the new fields (`near_zero_reference`, `b_overflow`, `*_withheld`) and `numerics_version: 2`.

## Independence of the numerical tests

- `tests/reference.py` computes every metric with Python `Fraction` (every float64 is an exact rational) and 60-digit `Decimal` square roots. It shares no code with `weightlab.analysis`.
- Hypothesis tests (`tests/unit/test_accumulate.py`) compare the streaming accumulators with that reference at rtol 1e-12. They cover:
  - any chunking;
  - NaN/±Inf mixes;
  - inputs scaled from 2^-1074 to 1.7e308;
  - B − A overflow.

  Beyond the 100–400 examples per CI run, a one-off stress run of 5,000 examples per property passed.
- Fixture reports are checked against the values written by `scripts/generate_demo_fixtures.py`, which knows nothing about WeightLab:
  - `base_full`/`ft_full`;
  - the 10 changed positions;
  - `rms_of_delta`;
  - LoRA `delta_full` per module;
  - the precision-overflow index.
- LoRA tests check the Gram-trace norm against a direct NumPy product and the `fan_in_fan_out` layout against a hand-built Conv1D golden.
- Benchmark `b05`/`b06` expectations are recomputed with plain NumPy by the harness.
- **Mutation check:** 7 deliberate bugs were injected, one at a time. The suite caught every one:
  - LoRA scale;
  - rsLoRA formula;
  - tie without evidence;
  - overflow not withheld;
  - relative-L2 denominator;
  - `fan_in_fan_out` layout;
  - attestation ignored.

## Read-only guarantees and provenance

- Inputs are opened read-only, and the CLI refuses any output path inside an input directory. Tests check that the input files keep the same SHA-256, mtime and size after a run.
- Every report records:
  - the tool, parser and numerics versions;
  - the per-input file names, sizes, mtimes and SHA-256 (when computed);
  - the tensor counts and bytes;
  - the operation definition and coverage (`complete`, no sampling);
  - `read_only: true`;
  - whether paths are included.
- `--consistency verified` hashes inputs before and after the run and fails with `FILE_CHANGED` on any difference.

## Known limitations

1. **Formats:**
   - only SafeTensors is supported;
   - checkpoints with F8/F6/F4/complex dtypes are rejected by the Phase 0 reader;
   - I64/U64 deltas are exact before one rounding, but norms and cosine of I64/U64 values above 2^53 use float64-rounded inputs (`rounded`, as doc 05 §2 allows).
2. **Matching:**
   - matching is by exact key only; renamed keys are reported as suspected and never compared;
   - Class S/L says nothing about permutation symmetry, and raw deltas between independently trained models can be meaningless.
3. **Layer and role labels** come from key-name heuristics (Llama/Qwen/GPT-2/BERT patterns). Unrecognized keys get role `other` and layer `null`.
4. **LoRA support** covers the documented subset only. These fail closed:
   - DoRA, embedding/conv LoRA, `modules_to_save`;
   - trained bias, `lora_bias`, QA-LoRA;
   - `trainable_token_indices`, `target_parameters`;
   - `layer_replication`, `layers_pattern`;
   - regex patterns;
   - non-`LORA` PEFT types.

   Modules whose estimated working set exceeds 384 MiB are skipped. The Gram-trace norm is withheld when its signed sum cannot be told apart from cancellation.
5. **Precision:**
   - metrics are float64 and exact up to rounding;
   - results below 2^-1022 (subnormal) carry only absolute precision;
   - a tensor or module whose B − A (or computed W + s·B@A) overflows float64 has its delta metrics withheld, and the report is marked incomplete.
6. **Performance:**
   - throughput is single-threaded, about 230 MiB/s per side on dense BF16 on this machine. Estimated: a 7B BF16 pair takes about 1 minute, a 70B pair about 10 minutes;
   - only LoRA has a compute budget. There is no wall-clock or read budget (`max_wall_seconds`, `scan_read_budget_mib`) yet; Ctrl-C cancels cleanly.
7. **Consistency:**
   - the default `best_effort` mode cannot detect a same-size rewrite that preserves the mtime (as in Phase 0);
   - `verified` costs two extra full reads.
8. **Hugging Face cache verification** needs the declared repo, a revision that resolves in the cache, and LFS blobs named by SHA-256. Without a matching revision the result is L, never V.
9. **Windows:**
   - not validated;
   - the Ctrl-C test is skipped there;
   - all 19 Phase 0 Windows CI failures were `FILE_CHANGED` on open, because a fresh `os.stat` can lag behind the handle right after a write. `path_identity()` now compares fstat of a freshly opened handle on Windows. CI has not confirmed the fix.
10. **Measurements** come from one machine. Linux and Windows numbers will come from the CI artifacts of this revision (the round-1 artifacts had invalid Linux/Windows memory figures; see above).

## Specification discrepancies and decisions needing ADRs (spec not edited; frozen per ADR-019)

**Discrepancies:**

- doc 12 names `PATH_OUTSIDE_ROOT` for lexical index paths, but the frozen fixtures expect `INVALID_FORMAT`. The fixtures were followed (as in Phase 0).
- doc 13 §3 still says "sine matrix".
- docs 03, 13, 16 and 18 say Python 3.11+, but the pinned toolchain requires 3.12+.

**Decisions taken in implementation that need ADRs:**

- a dtype mismatch within a float family stays comparable and caps the class at L; across numeric families it is X;
- V is capped at L when output-head tying or dtypes differ;
- the default `epsilon_norm` is 1e-12;
- the report schema lives in `weightlab/schemas/` rather than `contracts/`;
- the Hugging Face cache containment root defaults to `models--org--name`;
- regex `rank_pattern`/`alpha_pattern` keys fail closed;
- exit code 3 means "report written but incomplete";
- the default `chunk_elements` is 2^18;
- benchmark memory bounds use footprint / `VmHWM` / peak working set (`weightlab.core.memory`), not `ru_maxrss`.
- withheld (overflowed/unsupported) delta metrics make a report incomplete;
- limits on options: ε in [1e-300, 1], `max_lora_gmac` ≤ 1e6, `chunk_elements` ≤ 2^26, LoRA r ≤ 65536, module working set ≤ 384 MiB;
- a local `base_model_name_or_path` counts as a path for `--include-paths`.
